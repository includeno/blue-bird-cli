# 認証コードと CLI 機能の権限

[ドキュメント](README.md) · [English](../en/authorization.md) | [简体中文](../zh-CN/authorization.md) | 日本語

データ操作には明示的なモードが必要です。所有者は `--full-access`、範囲を限定したエージェントは `--code CODE` または `BLUEBIRD_CODE` を使います。コードは **利用できる CLI 機能** と **許可するタグ ID** を個別に制限し、両方の条件を満たす操作だけを許可します。macOS のアクセシビリティ権限とは別です。先に[システム設定](setup.md)を完了してください。

## ローカル管理画面で作成

```sh
bluebird start web
# ポートを指定する場合。0 は空いているポートを選択します。
bluebird start web --port 0
```

`start web` は所有者用の管理入口で、`--full-access` は不要です。`--code` と空でない `BLUEBIRD_CODE` は拒否するため、所有者は起動前に環境変数を解除してください。以前のトップレベル `web` コマンドを置き換えています。

どちらかを実行し、JSON 出力の専用 URL を開きます。サーバーは `127.0.0.1` のみで待ち受けます。既定ポートは 8765 です。管理中はプロセスを起動しておき、Ctrl+C で終了します。`start web` は開始と終了のレコードを出力し、結果を一つ返す業務コマンドとは異なります。

ホーム（`/`）には概要と CLI の使い方を表示します。認証コード一覧（`/codes`）に移動し、一覧上部の **新規作成** からダイアログを開きます。編集もダイアログを使います。キャンセル、閉じる、Escape で未保存の変更を破棄できます。

1. ページ上部で英語、中国語、日本語を選択します。
2. 「Codex · 仕事」など、識別できる名前を入力します。
3. Bluebird の既存タグを一つ以上選択します。必要なタグがなければアプリで作成し、画面の更新ボタンを押します。
4. CLI 機能を一つ以上選択します。グループのチェックボックスはグループ全体を選択・解除し、一部選択時は混合状態になります。「すべて選択」「すべて解除」は全機能が対象です。タグを選択しても機能は自動で許可されません。
5. 生成された完全なコードを保存します。一度だけ表示され、一覧から再取得できません。非表示、画面移動、更新、別の作成・編集ダイアログを開くと完全な値は消去されます。紛失時は古いコードを失効させて再作成します。
6. 「権限を設定」で同じコードの機能とタグを変更します。機能の概要を展開すると個別の許可を確認できます。「失効」は永久にコードを無効化します。変更は次のコマンドから適用され、すでに開始した UI 操作は取り消しません。

専用 URL の値は一時的な管理セッショントークンで、エージェントのコードではありません。エージェントには管理 URL を渡さないでください。ページは読み込み後に URL のフラグメントを除去し、トークンをメモリ内だけに保持します。ブラウザーの再読み込みや新しいタブには元の URL が必要です。画面内の更新ボタンはセッションを維持します。サーバー再起動で古い管理 URL は無効になります。

## 機能ごとの設定

| グループ | 個別に選択できる機能 |
|---|---|
| 照会 | `list`、`get`、`tags`、`logs` |
| タスク操作 | `add`、`update`、`complete`、`reopen`、`delete` |
| タイマー操作 | `timer.status`、`timer.start`、`timer.stop`、`timer.finish`、`timer.reset` |

ドットは保存する権限名です。実際の CLI は `timer status` などを使います。権限は互いを含みません。`add` を許可しても `list` は許可されず、開始の許可は停止の許可を含みません。照会専用コードは、対象タグ内でも更新できません。`--dry-run` にも実行と同じ権限が必要です。変更コマンドは別の照会権限がなくても、自身が変更したタスクやタイマーの結果を返します。

`capabilities`、`locales`、ヘルプは認証不要です。有効なコードは `auth-status` で自身の機能とタグを確認できます。システム設定やアプリ全体に関わる `setup`、`doctor`、`ui`、`open`、`focus` は full-access 専用です。コードで全 14 機能を選択してもタグ制限は残り、管理権限は与えられません。

## コードの使用

```sh
export BLUEBIRD_CODE='bb_REPLACE_WITH_YOUR_CODE'
bluebird auth-status
bluebird list
bluebird add '提案を書く' --tags '仕事'
bluebird update ID --notes '構成を作成済み'
bluebird delete ID --dry-run
bluebird delete ID --yes
unset BLUEBIRD_CODE
```

例には `list`、`add`、`update`、`delete` と、既存の「仕事」タグの許可が必要です。`--code CODE` は環境変数より優先され、明示的な `--full-access` は環境変数を無視します。二つのフラグは同時に指定できません。コードを共有ログやコマンド履歴に残さないでください。拒否されたエージェントが自動で full-access に切り替えてはいけません。

`auth-status` はモード、機能、タグ ID、現在のタグ名を返します。`capabilities` は機能グループを公開します。権限拒否は JSON `access_denied` と終了コード **3** です。その他は 0 成功、1 実行エラー、2 引数エラーです。

## タグの条件

タスクには一つ以上のタグが必要で、**すべてのタグが許可範囲内**でなければなりません。「仕事」だけのコードでは、タグなしや「仕事 + 個人」のタスクにはアクセスできません。「仕事 + 学習」を許可したコードは、いずれかまたは両方のタグを持つタスクを操作できます。

タグ ID に紐付くため、名前の変更では権限を維持します。同名タグを削除して作り直しても権限を引き継ぎません。存在しないタグはアクセスを許可しません。作成時は空でない `--tags` を明示し、変更後も既存の許可タグを一つ以上残す必要があります。コードでは新規タグの作成や全タグの解除ができません。同名タグが曖昧な場合は拒否します。full-access では作成・解除を引き続き使えます。

一覧や記録には対象内のタスクだけを返します。ID 指定では不存在と権限外を区別しません。対象外のタイマーは情報を隠して `state: unavailable` を返し、操作も拒否します。別の `--db` スナップショットは使えません。誤操作を防ぐため、画面のタスク特定では範囲外を含む同名タスクも確認します。

## 保存場所と制約

認証情報は `~/Library/Application Support/bluebird-cli/authorization.sqlite3` に、所有者だけが読み書きできる権限で保存します。完全なコードは保存せず、SHA-256 ダイジェストと権限情報だけを保存します。`BLUEBIRD_CLI_HOME` やヘルパーキャッシュから独立しているため、再コンパイルで権限は消えません。このファイルを削除すると全コードが無効になります。バックアップは非公開で保管してください。自動有効期限はありません。機能権限のない旧レコードは、管理者が編集するまで機能を許可しません。

Web サーバーは権限管理時だけ必要です。停止中も CLI はローカル認証 DB でコードを検証できます。管理 API はループバック Host、Origin、管理トークンを検査し、エージェントコードを管理認証に使わせません。

これは協調的な CLI 権限管理であり、**OS のセキュリティサンドボックスではありません**。同じ macOS アカウントで任意のコマンドを実行できる利用者やエージェントは、full-access の選択、認証 DB の変更、アプリデータの直接読み取りが可能です。その能力を信頼しない場合は実行環境にも制限が必要です。CLI コードは macOS やエージェントのサンドボックス権限を付与しません。
